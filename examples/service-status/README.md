# Service status

Live status of the services a platform team depends on (GitHub, Cloudflare), from their public Statuspage summaries: every component with its status, and how many are not operational per service. Cloudflare lists hundreds of components (one per data centre), GitHub a dozen, so compare shares, not counts.

**Open it in Seebra:** [as a board from git](https://www.seebra.io/?board=git%3Ahttps%3A%2F%2Fgithub.com%2Fseebra-io%2Fexamples%23examples%2Fservice-status) (read only, with this folder's history) · [from Explore](https://www.seebra.io/?example=service-status)

## This folder

- The board's folder is a git working tree (.seebra format 2): code in `queries/`, `transforms/` and `graphs/`, named after the steps; data kept with the board in `data/`; the board's state in `.seebra/` (one JSON per step, `seebra.json` naming the board).
- Data results aren't kept, except what `data/` holds: the rest comes back when the board runs.
- Generated by `frontend/scripts/examples-to-git.mjs` from the bundled example. Change the example in Seebra's repository and run the script again, or edit the board in Seebra (Open from git…, Edit in this clone, Commit…, Push).
